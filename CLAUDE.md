# UniCoach — proje notları

YKS/LGS öğrenci yardım sistemi (ders projesi). Önce web, sonra **aynı API'yi kullanan** mobil uygulama.
Modüller: konu anlatımı (YouTube linkleri), soru bankası, geçmiş sorulardan sınav, YKS tercih. Kapsam YKS (TYT/AYT) ve LGS; tercih modülü yalnızca YKS içindir. İçeriği öğrenci kendisi ekler (YouTube bağlantıları, soru kitabı PDF'leri).

## Yapı (npm workspaces)

| Yol | Ne |
|---|---|
| `apps/api` | NestJS 11 + Prisma 6 + PostgreSQL. Tüm iş mantığı burada. Uç noktalar `/api/*` altında. |
| `apps/web` | Next.js 16 (App Router) + Tailwind 4. `/api/*` istekleri rewrite ile API'ye gider. |
| `apps/mobile` | Expo SDK 58 / React Native 0.88 + Expo Router (`src/app`). Aynı `shared` ve `design` paketlerini kullanır. |
| `packages/shared` | Ortak tipler, `createApiClient`, sınav sabitleri, net hesabı. Web ve mobilde tekrar yazılmaz. |
| `packages/design` | Tasarım token'ları (tek kaynak). `dist/theme.css` → Tailwind; TS nesneleri → mobil. |

Paketler `dist/` dizinine derlenir (CommonJS). Uygulamalardan önce `npm run build:packages` çalıştırılmalıdır.

## Kurallar

- **Arayüz işinden önce [`docs/DESIGN.md`](docs/DESIGN.md) oku.** Tasarım dili "Modern & sakin"dir (indigo, yuvarlak kartlar). Bileşenlerde yalnızca anlamsal token sınıfları (`bg-surface`, `text-text-muted`, `bg-primary` …) kullanılır; ham hex veya `bg-indigo-600` kullanılmaz.
- Token değişirse `packages/design/src/tokens.ts` ve `docs/DESIGN.md` birlikte güncellenir.
- Web bileşenleri `apps/web/components/ui` altındadır. Mobilde aynı ad ve aynı prop'larla karşılıkları yazılır.
- Arayüz metinleri Türkçedir, "sen" diliyle yazılır.
- Yeni API uç noktası eklenirken yanıt tipi önce `packages/shared` içine eklenir, istemciler o tipi kullanır.
- Şema değişikliği: `apps/api/prisma/schema.prisma` güncellenir, ardından `npm run db:migrate` (yerel Postgres gerekir) çalıştırılır. Migration dosyaları commit'lenir.
- `docker compose up --build` her zaman çalışır durumda kalmalıdır, çünkü hoca projeyi bu komutla test edecek.
- **Giriş akışı (e-posta öncelikli, tek sayfa `/giris`):** e-posta → `POST /api/auth/check-email` → kayıtlıysa şifre adımı, değilse kayıt adımı (Ad, Soyad, Şifre) → kayıttan sonra şifre adımı. E-posta yalnızca `components/auth-flow.tsx` bileşeninin state'inde tutulur (URL veya storage yok); sayfa yenilenince akış baştan başlar. `/kayit` → `/giris` yönlendirmesidir.
- **Roller:** `STUDENT` (varsayılan) ve `ADMIN`. Admin kısayolu: e-posta `admin` + şifre `admin` ile kayıt olan hesap ADMIN olur (`ADMIN_SHORTCUT`, `isAdminShortcut` — packages/shared). Rol yalnızca API'de belirlenir. Bu kısayol ders projesi için kullanıcı isteğiyle eklendi; gerçek yayında kaldırılmalıdır.
- **Şifre kuralları:** 6–16 karakter, en az 1 büyük harf, en az 1 rakam (`PASSWORD_RULES`; admin kısayolu muaf). Kullanıcı adı ve soyadı ayrı tutulur (`firstName`, `lastName`).
- **Oturum:** API `POST /api/auth/register|login` JWT (7 gün) döndürür, `GET /api/auth/me` belirteci `Authorization: Bearer` başlığından (mobil) ya da `uc_session` çerezinden (web) okur. Web'de çerezi Next.js server action'ları (`app/(auth)/actions.ts`) httpOnly olarak yazar. Korumalı uç noktalarda `@UseGuards(AuthGuard)` ve `@CurrentUser()` kullanılır. Şifreler `node:crypto` scrypt ile özetlenir.
- **Web route grupları:** `app/(app)/*` giriş gerektirir (layout'ta `requireUser()`), `app/(auth)/*` giriş ve kayıt ekranlarıdır. Doğrulama kuralları `packages/shared/src/auth.ts` içindeki zod şemalarıdır; form, API ve mobil aynı şemayı kullanır.
- **Konu Anlatımı = öğrencinin kişisel YouTube kütüphanesi** (resmî müfredat ya da konu bölümü yok). Ders (sabit liste, `SUBJECTS` — packages/shared/src/library.ts; TYT/AYT/LGS dersleri ayrı) → kaynak grubu (`Source`: eklenen video ya da oynatma listesi, yeniden adlandırılabilir) → videolar (`SourceItem`, YouTube sırasıyla `position`; aynı video listede iki kez geçebilir). Kaynaklar yalnızca ekleyen öğrenciye görünür; ilerleme (`positionSec`, `watchedAt`) doğrudan `SourceItem`'da tutulur.
- **YouTube API anahtarı kullanılmaz.** Liste videoları tarayıcıda IFrame oynatıcının `getPlaylist()` metoduyla (en fazla 200, `PLAYLIST_MAX_ITEMS`) alınıp API'ye gönderilir; başlıklar API'de oEmbed ile çekilir (`apps/api/src/sources/youtube.ts`). Video bitince ya da %90'ı geçince (`WATCHED_THRESHOLD`) izlendi sayılır. Ana sayfadaki "Konu ilerlemen" kartı (web ve mobil `TopicProgressCard`, hesap `libraryProgress`): toplam izlenen video oranı, "Kaldığın yerden devam et" (en son çalışılan, bitmemiş kaynak) ve derslere göre ilerleme (en son çalışılan ders önce, en fazla 6). Son çalışma `SourceSummary.lastStudiedAt`: izlenen ya da yarım kalan videoların en son `updatedAt`'i (yeni eklenen videolar sayılmaz).
- **Soru Bankası = öğrencinin soru kitabı PDF deposu** (soru/şık girişi yok; soru çözme ve doğru/yanlış hesabı ileride ayrı "Çalışma alanı" modülünde). Ders (`SUBJECTS`) + isteğe bağlı serbest konu etiketi (`QuestionBook.topic`). Yükleme iki adımlıdır: `POST /api/books` (ad, ders, konu, boyut) → `PUT /api/books/:id/file` gövdesi ham PDF (`Content-Type: application/pdf`; web'de ilerleme için XHR, `lib/upload.ts`). En fazla 300 MB (`BOOK_MAX_BYTES`), ilk baytlar `%PDF-` olmalı. Dosyalar diskte `UPLOAD_DIR/books/<id>.pdf` (varsayılan `apps/api/storage`, Docker'da `uploads` volume'u). `GET /api/books/:id/file` Range destekler; web görüntüleyicisi (pdf.js, `lib/pdf.ts`) yalnızca gereken sayfaları indirir. Kalınan sayfa `lastPage`, sayfa sayısı ilk açılışta `pageCount` olarak kaydedilir. Next rewrite'ı büyük yükleme için `experimental.proxyClientMaxBodySize` ile açıldı.
- **Soru çıkarma (Soru Bankası → `/soru-bankasi/[id]/sorular`):** PDF'teki sorular metin olarak değil, sayfa + kutu (PDF noktası, sol üstten) + doğru cevap olarak `BookQuestion`'da saklanır; sınavda kutu PDF'ten resim olarak çizilir. Şık metinleri girilmez (şıklar görselin içinde; `choices` alanı boş kalır). Bulma tarayıcıda yapılır (`packages/shared/src/question-detect.ts`; düzenleyicinin platformdan bağımsız kuralları — sayfada bul, tüm PDF'i tara, kutudan yeni soru, yeni test başlat, elle anahtar, kayıt gövdesi — `question-editing.ts`'te, web ve mobil aynısını kullanır): metin katmanı olan sayfalarda sütun kenarındaki "12." numaraları ve "A)–E)" şıkları, taranmış sayfalarda (metin < 40 karakter) Tesseract OCR (`lib/ocr.ts`, `tesseract.js`, Türkçe dil verisi ilk kullanımda CDN'den iner) ile şık kümeleri. Öğrenci her PDF için iki yöntem seçer (`QuestionBook.detectMethod`: auto/text/ocr; `keyMethod`: auto/lastPages/pageBottom/none — `DETECT_METHODS`, `ANSWER_KEY_METHODS`, packages/shared): cevap anahtarı ya ayrı sayfadadır (ÖSYM; test adıyla, yoksa sırayla eşlenir) ya da her sayfanın altındaki "1.A 2.D…" şerididir (o sayfanın sorularına numarayla). Yeni bir yayınevi düzeni çıkınca buraya yeni bir yöntem eklenir. Otomatikte PDF'in çoğu metinliyse metinsiz sayfalar (kapak) OCR'a gönderilmez. Numaralar sırayla ilerler, 1. soru her görüldüğünde yeni test açılır; test adları tekildir (başlık testin sonraki bir sayfasında yazıyorsa o teste verilir). OCR sonucu yalnızca öneridir; öğrenci düzenleyicide kutuları sürükler/çizer, numara, test ve cevabı düzeltir. Kayıt `PUT /api/books/:id/questions` ile tüm liste gönderilerek yapılır; kayıtlı soruların `id`'si gönderilir ve korunur (silinenler silinir, yalnızca değişenler güncellenir) ki sınavlardaki bağlantılar kopmasın. Aynı testte aynı numara olamaz (zod ile denetlenir; veritabanında tekil kısıt yok). Düzenleyici `?soru=<id>` ile o soruyu açıp seçer.
- **Geçmiş Sınavlar (`/sinavlar`):** Soru Bankası'nda çıkarılan, cevabı girilmiş sorularla süreli deneme (`Exam`, `ExamQuestion`; packages/shared/src/exam-session.ts). Sınav kurulurken sorular (yer + doğru cevap) kopyalanır ve kaynak soruya (`bookQuestionId`) bağlı kalır; sonuçtaki "Kaynağında düzenle" bağlantısı düzenleyiciyi açar. Süre sunucuda tutulur: bitiş = `startedAt` + `durationSec` + `extraSec` (ek süre) + `pausedMs` (duraklatmalar); `pausedAt` doluyken süre işlemez ve cevap kabul edilmez; süre dolunca ilk istekte sınav kapatılır. Sınav ekranında Duraklat/Devam ve "Süre ekle" var; sınav sayfasından çıkınca (başka sayfa, sekme kapatma, yenileme) süre otomatik duraklatılır (`pagehide` + çıkışta keepalive `POST …/pause`), dönünce "Devam et" ile sürer. "Kaynağında düzenle" (sınav sırasında ve sonuçta) süreyi durdurup düzenleyiciyi `?soru=…&sinav=…` ile açar; düzenleyicideki şeritten sınava dönülünce (`?devam=1`) sınav devam ettirilir ve sorular kaynaktan yeniden kopyalanır (`resume`/`sync`; bitmiş sınavda sonuç yeniden hesaplanır). Her cevap hemen kaydedilir (`PUT /api/exams/:id/answers/:qid`); doğru cevaplar yalnızca sınav bitince gönderilir. Net: YKS'de 4, LGS'de 3 yanlış 1 doğruyu götürür (`examNet`); sınavın türü PDF'in dersinden gelir. Önerilen süre soru başına TYT/LGS oranıyla (`suggestedMinutes`). Ana sayfadaki "Son deneme" kartı son biten sınavı gösterir.
- **YKS Tercih (`/tercih`):** önce öğrencinin sonucu alınır (`YksResult`, yıl başına bir kayıt, `PUT /api/results/:year` üzerine yazar; packages/shared/src/yks-result.ts). İki yol: ÖSYM sonuç belgesi (Sonuç Açıklama Sistemi sayfasının PDF çıktısı; metin katmanı var) ve elle giriş (`components/tercih/result-form.tsx`; belgedeki her bilgi girilebilir ama **zorunlu olan yalnızca yerleştirme puanı + başarı sırası**, en az bir puan türünde ve ikisi birlikte — zod'da da denetlenir; ham puan, ek puanlı, OBP, diploma notu ve netler "Diğer bilgiler"de isteğe bağlı; test adları ve soru sayıları `YKS_RESULT_TESTS`). Kayıtlı her sonuç aynı formla düzenlenir (yıl değişmez); belgeden okunan sonuç değiştirilerek kaydedilirse kaynağı `manual` olur. Belge tarayıcıda pdf.js ile okunur (`lib/yks-result-pdf.ts`), ayrıştırma ortak pakettedir (`parseYksResult`, satırları y'ye göre kümeler: puan tablosu TYT/SAY/SÖZ/EA/DİL satırları — puan, sıra, yerleştirme puanı/sırası, ek puanlı; OBP ve diploma notu sütun başlığına göre; doğru/yanlış tablolarında her "Doğru | Yanlış" çiftinin adı üstündeki en yakın metindir). **PDF sunucuya yüklenmez, T.C. kimlik no ve ad soyad API'ye gönderilmez**; ad yalnızca ekranda hesap adıyla karşılaştırılıp uyarı için kullanılır. Puanlar ve testler `Json` olarak saklanır, zod ile denetlenir. Programlar (`/tercih/programlar`): kaynak YÖK Atlas'ın kendi sitesinin kullandığı JSON API'si (`POST https://yokatlas.yok.gov.tr/api/tercih-kilavuz/search`, gövde `{filters, page, size, sortBy, direction}`; belgelenmemiş, alan eşlemesi yalnızca `apps/api/src/programs/atlas.client.ts`'te). İki kaynak, aynı filtre ve aynı yanıt (`ProgramPage`, packages/shared/src/programs.ts): **indirilmiş veri** (`Program`, `ProgramCondition`, `ProgramSync`; tüm kılavuz ~22 istekte indirilip tablo baştan yazılır; tablo boşsa API açılışta kendiliğinden indirir — `ATLAS_AUTO_SYNC=false` kapatır —, sonra yalnızca admin "Veriyi güncelle" ile) ve **canlı** (istek sunucudan YÖK Atlas'a iletilir). Yerel arama YÖK Atlas'la aynı sonucu aynı sırada vermelidir (sıraya göre, boşlar sonda; sıra aralığı verilince sırası boş programlar da dahil). `sonuc-aciklandi` 0 ise kılavuzun taban puanları bir önceki yılındır. Puan türü olmayan (özel yetenek) programlar alınmaz. Öğrencinin en yeni sonucundaki yerleştirme sırası, programın **sonuç yılına en yakın yılının** (taban sırası olan; eşitlikte yenisi — `comparisonYear`) sırasıyla karşılaştırılır (yalnızca ipucu, `rankComparison`); uyarılar da bu yıla göredir. Programların bütün yılları (kılavuz yılı + önceki üç) puan ve sırasıyla gösterilir, karşılaştırılan yıl vurgulanır (`ProgramYears`). Tercih listesi (`/tercih/liste`, `Preference`, packages/shared/src/preferences.ts): öğrenci istediği programı ekler (en fazla 24, ÖSYM sınırı — tek sert kural); puanına ya da koşullara uymayan program **engellenmez, yalnızca uyarı** gösterilir (`preferenceWarnings`: puan türünde yerleştirme puanı yok, en düşük başarı sırası şartı, taban sıranın gerisinde/sınırda, KKTC uyruklu ve M.T.O.K. kontenjanları). Program kodla eklenir: önce indirilmiş veride, yoksa canlı YÖK Atlas'ta (`kilavuzKodu` filtresi) aranır ve eklendiği hâliyle `snapshot` olarak da saklanır; liste gösterilirken indirilmiş veride varsa güncel hâli kullanılır. Sıra yukarı/aşağı ile değişir (`PUT /api/preferences/order` tüm kodları alır); değiştiren her uç listenin son hâlini döndürür.
- **Çalışma Alanı (`/calisma-alani`):** solda video (üstte) ve not defteri (altta), sağda PDF. Geniş ekranda (≥1024px) bölmeler arasındaki tutamaklar sürüklenerek boyutlandırılır (sol sütun %20–80, video %12–85; `localStorage` `uc_workspace_layout`, "Düzeni sıfırla"); video bölmesinde video alanı kalan yüksekliği doldurur (YouTube kenarları siyahla doldurur), kontrol şeridi tam genişlikte kalır. "Tam ekran": tarayıcı tam ekranı (`requestFullscreen`, F11 gibi; izin yoksa yalnızca pencere içi) + çalışma alanı `fixed inset-0` ile tüm ekranı kaplar; `html[data-workspace-expanded]` site başlığını yukarı gizler, fare üst kenara (6px) gelince `data-header-open` ile yüzen şerit olarak iner (globals.css). Esc ya da PDF başlığındaki düğme çıkar; tarayıcı tam ekranından çıkılınca mod da kapanır. Bölmelerin yerini değiştirme sonra eklenecek. Video ve PDF yeni bileşen değildir: Konu Anlatımı oynatıcısı `useSourcePlayer` (components/library/use-source-player.tsx; oynatıcı, kontroller, tam ekran, kısayollar ve ilerleme kaydı) ve Soru Bankası görüntüleyicisi `BookReader` (components/question-bank/book-reader.tsx; `embedded` iken pencere yerine kendi kutusunda kayar) iki yerde de kullanılır. Seçimler adreste (`?video=&pdf=&defter=`) ve `localStorage`'da (`uc_workspace`) tutulur; video ve PDF sayfalarında "Çalışma alanında aç" bağlantısı var. Not defteri (`Notebook` → `NotebookPage`, packages/shared/src/notebooks.ts): defter adı + sayfalar (en fazla 200; son sayfa silinemez); sayfa içeriği `{ strokes, texts }` JSON'udur — kalem/marker çizgileri düz nokta dizisi, metin kutuları konum/genişlik/renk/boyut — koordinatlar ekrandan bağımsız 1000×1414 sayfa düzleminde. Silgi dokunduğu çizgiyi ya da metin kutusunu bütün olarak siler. Çizim tarayıcıda canvas ile (`components/workspace/note-canvas.tsx`), geri al/yinele ve kayıt `notebook-panel.tsx`'te: her değişiklik 0,8 sn sonra `PUT /api/notebooks/:id/pages/:pageId` ile tüm sayfa gönderilerek kaydedilir; sayfa/defter değişmeden önce bekleyen kayıt gönderilir, sekme kapanırken keepalive denenir.
- **Mobil (`apps/mobile`):** Expo SDK 58, Expo Router (`src/app`; `@/` → `src/`). Expo sürekli değiştiği için mobil koduna dokunmadan önce `apps/mobile/AGENTS.md`'deki kurala uy: SDK 58 belgelerine bak (https://docs.expo.dev/versions/v58.0.0/), paket eklerken `npx expo install` kullan (Expo Go yalnızca kendi paketlerini içerir). Monorepoda **tek React** olmalı: React Native renderer'ı React sürümünü birebir ister, bu yüzden web de `react@19.3.0`'a sabitlendi ve kökte `overrides` var; Expo SDK yükseltilirken ikisi birlikte değişir. TypeScript 5.9'da kalındı (`expo.install.exclude`). Kimlik: JWT `expo-secure-store`'da (web önizlemesinde localStorage), istekler `Authorization: Bearer` (`src/lib/api.ts`, `src/lib/session.tsx`); açılışta `GET /api/auth/me`, 401'de oturum kapanır, API'ye ulaşılamazsa "Sunucuya ulaşılamadı" ekranı. API adresi QR ile eşlenen adres (`uc_api_url`), yoksa `EXPO_PUBLIC_API_URL`, yoksa Expo'nun çalıştığı bilgisayarın adresi + `:4000` (telefon ve bilgisayar aynı Wi‑Fi'de olmalı; Windows güvenlik duvarı 4000'e izin vermeli). Ekranlar `Stack.Protected` ile oturuma göre: `giris` (web'deki e-posta öncelikli akış) ve `(app)` → `(tabs)` (Ana Sayfa, Konular, Soru Bankası, Sınavlar, Tercih; modül listesi `src/lib/modules.ts`, `ready` false olan modül "Mobilde yakında" gösterir — şu an hepsi hazır) + sekmelerin üstüne açılan `profil` (sağ üstteki fotoğraftan), `kaynak/[id]`, `kaynak-ekle`, `pdf/[id]`, `pdf-yukle`, `sorular/[id]` (`?soru=` ile o soru açılır), `sinav-yeni` (`?pdf=`), `sinav/[id]` (çözme ya da sonuç), `sinav-incele/[id]` (`?soru=&filtre=`), `tercih-sonuc` (`?yil=` düzenleme, `?yillar=` kayıtlı yıllar), `tercih-programlar`, `tercih-liste`, `calisma-alani` (`?video=&pdf=&defter=`; sekmesi yok, ana sayfadaki modül kartından ve kaynak/PDF ekranlarının başlığındaki defter düğmesinden açılır). Tema hesaptaki `theme`'dan (`src/lib/theme.tsx`, renkler `@unicoach/design` `semantic`'ten), yazı tipi Inter (`@expo-google-fonts/inter`). Arayüz bileşenleri `src/components/ui` (Button, Card, Input, Badge, SegmentedControl, Text, Screen, useDialog, ToolButton/ToolGroup) web'dekilerle aynı ad ve prop'larla. Modüller sırayla mobile taşınır; iş mantığı (filtreler, kaldığı yerden başlatma, biçimlendirme) iki platformda yazılmaz, `packages/shared`'a taşınır (ör. `subjectFilters`, `startSeconds`, `formatDuration`, `groupByTopic`, `bookTopics`). Alttan açılan pencere `components/ui/Sheet` (ders seçimi, PDF bilgileri). **Mobil Konu Anlatımı:** YouTube oynatıcısı, IFrame API'yi çalıştıran küçük bir HTML sayfasıdır (`src/lib/youtube.ts` `playerHtml`): telefonda `react-native-webview` içinde (`components/library/youtube-frame.tsx`), web önizlemesinde `srcdoc` iframe'inde (`youtube-frame.web.tsx`); sayfa saniyede bir konum, durum değişikliği ve hata mesajı gönderir, uygulama `load/play/pause` komutu verir. YouTube, Referer'sız yerleştirmede "Hata 153" verdiği için HTML bir https köküyle (`PLAYER_ORIGIN`, `baseUrl`) yüklenir — sunucusu yoktur. Mobilde YouTube'un kendi kontrolleri kullanılır. Oynatma listesinin videoları web'deki gibi görünmeyen bir oynatıcının `getPlaylist()` sonucundan alınır (ekran dışında 200×120; Android sıfır boyutlu WebView'i çalıştırmayabilir). İlerleme kuralları web'le aynıdır: oynarken 10 sn'de bir, duraklatınca, video değişince, uygulama arka plana geçince (video da durur) ve ekrandan çıkınca kaydedilir; bitince izlendi + sıradaki. Uygulama dikey kilitlidir (`app.json`); yalnızca oynatıcı ekranı `expo-screen-orientation` ile döndürmeyi açar, yatayda video ekranı kaplar. YouTube'un tam ekran düğmesi (WebView `allowsFullscreenVideo`) sayfada `fullscreenchange` ile yakalanıp uygulamaya bildirilir: girişte ekran yataya kilitlenir, çıkışta dikeye kilitlenip 1,5 sn sonra kilit kalkar (react-native-webview çıkışta kendi kaydettiği yönü geri yükler, bu yüzden yön her seferinde açıkça verilir). **Mobil Soru Bankası:** liste (filtreler, ders → konu grupları), PDF yükleme ve görüntüleme, ad/ders/konu düzenleme, silme ve soru çıkarma (`sorular/[id]`, PDF ekranının başlığındaki ✓ düğmesinden ya da PDF bilgilerinden). ## Komutlar

**Geliştirme makinesinde Docker kurulu değil** (2026-10-19, disk alanı yetersiz olduğu için kaldırıldı). Docker ile tam kontrol v1.0 yayınlandıktan sonra yapılacak (kullanıcı kararı). Geliştirme doğrudan Windows'a kurulu PostgreSQL 18 ile yapılır (`localhost:5432`, kullanıcı/şifre/veritabanı `unicoach`, kurulum: `scripts/setup-local-db.sql`). Dockerfile ve compose dosyaları korunur ama burada çalıştırılamaz: bunlara dokunan değişiklikler proje tesliminden önce Docker yeniden kurularak `docker compose up --build` ile doğrulanmalıdır.

```bash
npm install                                   # bağımlılıklar
psql -U postgres -h localhost -f scripts/setup-local-db.sql  # bir kez: unicoach kullanıcısı + veritabanı
npm run dev                                   # paketleri derler, API :4000 + web :3000
npm run build                                 # her şeyi derler
npm run typecheck
docker compose up --build                     # tam sistem (db + api + web)
npm run mobile                                # Expo (telefonda Expo Go ile QR kodu okut; API ayrıca npm run dev ile açık olmalı)
npm run web -w @unicoach/mobile               # mobil uygulamanın tarayıcı önizlemesi (:8081)
```
